0.1.5-audit25fix — 2026-09-18
- Tesles now creates and owns the persistent NPC population instead of depending on SCUM spawning NPCs first. A brand-new world deterministically generates 100 persistent TeslesNPCEntities and their 1-5 member squads before the HTTP server opens, and saves them immediately.
- The persistent identity is the Tesles entity, not the Unreal actor. A SCUM actor is only a materialized body: identity, traits, skills, stress, trauma, memories, relationships, squad membership, leadership, health and position survive restarts, and world.json never stores runtime actor state.
- World save schema v6 with migration. Legacy worlds keep every existing NPC and are topped up to the target exactly once; an initialized world is never regenerated, not even when all of its NPCs have died (replenishDead=false).
- NPCs are virtualized beyond 700 m. FULL <= 200 m, LIGHT 200-700 m, VIRTUAL > 700 m. A physical actor exists in FULL and LIGHT only.
- Dematerialization waits 5 s after the last player leaves the 700 m ring, so crossing the boundary cannot cause spawn/despawn flapping. A player returning inside the grace window cancels it.
- Added a materialization state machine (VIRTUAL, SPAWN_QUEUED, SPAWNING, MATERIALIZED, DESPAWN_GRACE, DESPAWN_QUEUED, CAPTURING, SPAWN_BACKOFF) with exponential spawn backoff. A failed spawn never moves the persistent entity and a failed or timed-out capture never destroys the actor: losing physical state is not an accepted fallback.
- Added a spawn queue with per-tick budgets (2 materializations, 5 dematerializations) ordered by player distance, squad cohesion, LOD and queue age, so a player teleporting into a dense region cannot burst dozens of SpawnActor calls in one tick.
- Bridge commands are now idempotent and keyed: spawn, despawn, navigation, aim, trigger and reload each have their own command key with a monotonic sequence, a stale ACK can never retire newer work, and STOP supersedes a pending MOVE for the same actor. The Lua reader de-duplicates per command key instead of one global sequence, so independent commands can no longer starve each other.
- New UE4SS spawn adapter: verified NPC class catalog, idempotent persistentNpcId -> actor map, Tesles identity tagging, capture-before-destroy transaction, destroy verification and an optional repeated spawn/destroy probe. No capability is reported OK before it actually succeeded on the running build.
- New UE4SS weapon adapter behind AIM / FIRE_START / FIRE_STOP / RELOAD. Node never names a SCUM function, the trigger is always released before an actor is captured or destroyed, and physical combat only becomes OK after a real weapon primitive works on this build.
- New compatibility profile module records every reflected class, function and property the adapters tried, with the exact outcome, into runtime\compat-profile.json.
- Vanilla brain takeover is now bound to Tesles-owned actors. An unmanaged SCUM NPC no longer becomes a Tesles entity by default (population.adoptUnmanagedNpc=false).
- Death is authoritative over materialization: a late spawn result for a dead entity is destroyed rather than bound, a stale spawn generation is rejected, and a capture snapshot can never heal or resurrect an NPC.
- Honest capability health. PENDING means a capability has not been exercisable yet, DEGRADED means it was attempted and failed, OK means it was proven in this bridge session. A fresh zero-player server now shows PENDING for the physical rows instead of a misleading DEGRADED, and physicalVirtualization only turns green after a full materialize -> capture -> destroy -> rematerialize roundtrip preserving identity.
- Map viewer shows persistent squads immediately: every persistent NPC has a marker whether or not a physical actor exists, markers ring-code materialization state, the NPC panel shows persistent ID, origin, body intent, resolved class, actual and desired LOD and any spawn block reason, and the top bar reports living, dead, physical and queued counts.
- Diagnostics bundle gained population-summary.json, materialization-events.json, pending-commands.log and compat-profile.json.
- Added brain/tools/restart-soak.js and a 50-cycle restart soak test proving identity, squads, deaths, successions and psychology survive repeated restarts, plus new population, materialization, spawn protocol and physical combat suites (264 tests).
- Map manifest is now generated from the tiles that actually ship (brain/tools/buildMapManifest.js), so the viewer can no longer advertise a zoom level whose tiles are missing. The bundled pyramid is zoom 0-4; restore deeper tiles and re-run the tool to advertise them again.
- Installer deploys the new configs and Lua modules, verifies package completeness before touching the server, records the SCUM build in the runtime config, and still preserves runtime\world.json and brain\config\user.json across updates.

0.1.5-audit20fix — 2026-09-17

- Root cause: audit19 started SCUM correctly, then discarded the trusted Start-Process object/PID and re-identified the process through Win32_Process.ExecutablePath. That property can be unavailable even while the process is alive, making exact-path CIM matching report a false negative.
- SCUM startup now uses an explicit PID handshake: the launcher verifies the child is alive, writes runtime\scum-server.pid, and the installer validates/stabilizes that exact PID with Get-Process instead of requiring CIM ExecutablePath visibility.
- SCUM stop now prefers the managed PID file, so update/uninstall can stop the exact process launched by Tesles even when CIM cannot expose ExecutablePath. Exact-path CIM matching remains only as a fallback for older/manual starts.
- For an older/manual start with no PID file, if Windows hides ExecutablePath and exactly one SCUMServer.exe exists, stop/detection safely fall back to that unique PID; multiple ambiguous SCUM processes fail closed instead of killing an arbitrary server.
- Added audit20 regression coverage for PID-based startup verification and managed-PID shutdown.
